A fix-up release for v0.6.0, "A Life for Every You", with what testers and a long end-to-end run turned up: memories that went missing when you switched worlds, ComfyUI launch scripts, slow catch-ups with many companions, and a handful of smaller fixes. If you have an earlier version, install over it (or run `update.bat` / `update.command` in a source copy). Your worlds, companions and everything they remember are kept, and the first launch makes a verified backup before updating.

## What's new

**On their mind**
- Companions can be any gender, so the app now talks about them as "they" unless a character's own pronouns say otherwise. "On her mind" is now **On their mind**.

**Start ComfyUI your own way**
- If you start ComfyUI with your own launch script (a `.bat`, `.cmd` or `.sh` file), you can now pick that script in Settings and the launch button runs it as it is, with your own options.
- Launch errors are plainer, a folder that isn't ComfyUI is refused with a reason, and example paths match your computer.

**Faster catch-ups with lots of companions**
- Coming back after a month away with 25 companions used to take about 11 seconds to catch up and now takes about 3. While a long catch-up runs, your own changes no longer fail with "database is locked".

**Clearer settings**
- Empty model settings such as temperature now say **Service default**, because a blank field lets the service you connect to pick the value, and that can differ between hosts of the same model.
- Searching Settings for "logging" or "full conversation" now finds **Record model calls**.

## What's fixed

- Memories from a world you then left are kept. Before, switching worlds while the app was still remembering something could throw it away.
- A companion made or imported in the evening (in the Americas) has a home and wardrobe straight away, instead of only after midnight.
- Instant local replies switch on once your local model server is up, even if it was still loading when you sent your first message.
- Importing a character from the Character page now shows the "is here" notice.
- The Messages, Posts and Character tabs stay at the top of a profile on every tab instead of scrolling away with the posts.
- Feed pictures keep the whole face in frame and show in their own shape. A post about several moments shows its picture under the moment it belongs to.
- A friend's post now says who they are to your companion ("Cynthia · Kimberly's mom"), not who they are to you.
- A persona with no name is never called "You".
- Weekly backups start right away instead of a week after the daily ones, and restoring a backup from the command line restores the world you're in.
- On a narrow phone the bottom bar fits the screen again.
- A first text that couldn't be used doesn't ask the model again on every check; it waits an hour.

## Install on Windows

**Installer (easiest):** download `ProsperoCompanion-0.6.1-win-x64-setup.exe` below and run it. It installs for your user only and doesn't need administrator rights, Python or Node. It adds Prospero Companion to the Start menu. It isn't code-signed yet, so Windows SmartScreen may say it "protected your PC": click **More info**, then **Run anyway**.

**Portable:** `ProsperoCompanion-0.6.1-win-x64.zip` is the same app without an installer. Unzip it anywhere and double-click `Prospero Companion.cmd` in the `ProsperoCompanion` folder.

**From source:** download the source code below (or `git clone` the repository), open the `Windows` folder, double-click `install.bat` once and then `launch.bat`. It can update itself later with `update.bat`, whether you cloned it or downloaded the ZIP.

Then open **Settings > Models**, add a model, and create your companion. `SHA256SUMS.txt` lists the checksums of the downloads.

## Install on a Mac

There's no Mac app yet. Download the source code below (or `git clone` the repository), open the `Mac` folder and double-click `install.command`, then `launch.command`. It needs Python 3.12+ and Node.js 22.13+ and installs them with Homebrew if you have it. The scripts aren't signed, so a downloaded ZIP needs **Open Anyway** in System Settings > Privacy & Security the first time. [Installing on a Mac](https://github.com/vantaloomin/prosperos-companion/blob/main/Program/docs/macos.md) walks through it.

By default your companion's data lives outside the program folder (`%LOCALAPPDATA%\ProsperoCompanion` on Windows, `~/Library/Application Support/ProsperoCompanion` on a Mac), so updating or reinstalling keeps it. Settings > Data shows where yours is.

## Known issues

- **Built-in recall needs a model file you download yourself.** The Companion suggests EmbeddingGemma 2 and Qwen3 Embedding 0.6B but never downloads a model for you. The llama.cpp builds it fetches for Mac haven't been run on a real Mac yet. On Linux, point `COMPANION_LLAMA_SERVER` at your own llama-server.
- **Not code-signed.** Expect SmartScreen warnings on Windows and a Gatekeeper block on the first Mac run.
- **Mac is untested on real hardware.** The scripts and tests pass on GitHub's Apple Silicon and Intel Macs only. LoRA training isn't available on a Mac.
- **Phone access** over Tailscale or home Wi-Fi is new, and testers have had trouble getting a phone to load. The new checks in Settings > Phone access say what's wrong.
- **Not yet tried on real setups:** the launch buttons with real installs of LM Studio, Ollama, KoboldCpp and ComfyUI, instant local replies, voice notes with real voices, Matchlight's Show photo, and the Local Pulse and Culture Pulse lookups (tested against recorded responses only).
- **Image generation** depends on your own backend. Krea 2 with ComfyUI has run on one Windows PC with an RTX 5090. Text inside pictures can come out garbled.
- **Real-city data** comes from general knowledge and is labeled as estimates.
