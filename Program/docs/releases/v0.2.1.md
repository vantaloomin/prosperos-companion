A smaller update with fixes from our testers, a new AI provider, and the option to keep your companion's data right beside the app. If you have an earlier version, install over it (or run `update.bat` / `update.command` in a source copy). Your companion and everything they remember are kept.

## What's new

**Keep your data with the app**
- Settings > Data now shows where your companion's data lives, with an **Open** button.
- **Move into the app folder** moves it all into a `Data` folder beside the app the next time you start. That's handy for running the Companion from a USB stick or another drive. Every file is checked before the switch, and the old folder is left in place with a note saying where it went. Cloud-synced folders, network drives and nearly full disks are refused, to keep your data safe.

**See when messages were sent**
- Messages and posts now say when they were sent, like "just now", "5 minutes ago" or "Yesterday 9:14 PM". Hover for the full date and time. This works in every chat style, and Retro IM shows the time before each name.

**NanoGPT**
- NanoGPT is now a built-in choice for both chat models and pictures. Pick it in Settings > Models or Settings > Images and add your key.
- Image backends have a **Connection** panel where you can change the name, model, key or address. Before, fixing a wrong model meant removing the backend and starting over.

**Bring your own cities more easily**
- A city file you made or got from someone else now loads even with small mistakes, like a misspelled neighbourhood, "Autumn" instead of "fall", or a kind of place the Companion didn't know yet. New kinds of places, schools and jobs are kept, and Settings > Cities lists what was added or adjusted.

## What's fixed

- **Mac:** running the app from an external drive no longer breaks Matchlight, the city pickers and the Today page with "Something went wrong". (Hidden "._" files that macOS leaves on those drives were being read as cities.)
- **Mac:** reinstalling after Homebrew updated Python no longer fails with "No module named pip". The installer rebuilds what it needs by itself, on Windows too.
- When something goes wrong, the error now says where the log file is, and on a PC an **Open the log folder** button takes you there.

## Install on Windows

**Installer (easiest):** download `ProsperoCompanion-0.2.1-win-x64-setup.exe` below and run it. It installs for your user only and doesn't need administrator rights, Python or Node. It adds Prospero Companion to the Start menu. It isn't code-signed yet, so Windows SmartScreen may say it "protected your PC": click **More info**, then **Run anyway**.

**Portable:** `ProsperoCompanion-0.2.1-win-x64.zip` is the same app without an installer. Unzip it anywhere and double-click `Prospero Companion.cmd` in the `ProsperoCompanion` folder.

**From source:** download the source code below (or `git clone` the repository), open the `Windows` folder, double-click `install.bat` once and then `launch.bat`. It can update itself later with `update.bat`, whether you cloned it or downloaded the ZIP.

Then open **Settings > Models**, add a model, and create your companion. `SHA256SUMS.txt` lists the checksums of the downloads.

## Install on a Mac

There's no Mac app yet. Download the source code below (or `git clone` the repository), open the `Mac` folder and double-click `install.command`, then `launch.command`. It needs Python 3.12+ and Node.js 22.13+ and installs them with Homebrew if you have it. The scripts aren't signed, so a downloaded ZIP needs **Open Anyway** in System Settings > Privacy & Security the first time. [Installing on a Mac](https://github.com/vantaloomin/prosperos-companion/blob/main/Program/docs/macos.md) walks through it.

By default your companion's data lives outside the program folder (`%LOCALAPPDATA%\ProsperoCompanion` on Windows, `~/Library/Application Support/ProsperoCompanion` on a Mac), so updating or reinstalling keeps it. Settings > Data shows where yours is.

## Known issues

- **Built-in recall needs a model file you download yourself.** The Companion suggests EmbeddingGemma 2 and Qwen3 Embedding 0.6B but never downloads a model for you. The llama.cpp builds it fetches for Mac haven't been run on a real Mac yet. On Linux, point `COMPANION_LLAMA_SERVER` at your own llama-server.
- **Not code-signed.** Expect SmartScreen warnings on Windows and a Gatekeeper block on the first Mac run.
- **Mac is untested on real hardware.** The scripts and tests pass on GitHub's Apple Silicon and Intel Macs only. LoRA training isn't available on a Mac.
- **Not yet tried on real setups:** phone access over Tailscale, Matchlight's Show photo, and the Local Pulse and Culture Pulse lookups (tested against recorded responses only).
- **Image generation** depends on your own backend. Krea 2 with ComfyUI has run on one Windows PC with an RTX 5090. Text inside pictures can come out garbled.
- **Real-city data** comes from general knowledge and is labeled as estimates.
